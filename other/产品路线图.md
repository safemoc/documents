产品路线图（Product Roadmap）是一份用来说明“产品未来要往哪里走、为什么这样走、什么时候大致做到”的规划文件。

它通常包含：

- 产品目标：想解决什么问题、实现什么业务结果
    
- 重点方向：未来优先投入哪些功能、用户场景或市场
    
- 时间阶段：近期、中期、长期分别推进什么
    
- 优先级：哪些事情先做，哪些可以延后
    
- 关键指标：如何判断路线图是否有效，例如用户增长、留存率、收入等
    

例如，一个外卖 App 的路线图可能是：

- 近期：优化下单流程，降低支付失败率
    
- 中期：上线会员体系，提高复购率
    
- 长期：拓展到生鲜和药品配送
    

需要注意的是，产品路线图不是详细的项目排期表。它更关注战略方向和优先级，而项目计划则会细化到具体任务、负责人和截止日期。

可以简单理解为：**产品路线图回答“做什么、为什么做、先做什么”；项目计划回答“谁来做、怎么做、哪天完成”。**

# 它和产品流程图 有什么区别?
它们关注的不是同一个问题：

| 对比项   | 产品路线图          | 产品流程图             |
| ----- | -------------- | ----------------- |
| 核心问题  | 产品未来做什么、为什么做   | 用户或系统具体怎么完成一件事    |
| 关注层级  | 战略与规划          | 操作与逻辑             |
| 时间范围  | 通常覆盖几个月到几年     | 通常描述某一个具体流程       |
| 主要内容  | 目标、方向、优先级、阶段   | 步骤、判断条件、页面跳转、异常分支 |
| 常见使用者 | 产品负责人、管理层、业务团队 | 产品经理、设计师、开发、测试    |
| 表现形式  | 时间轴、主题列表、阶段规划  | 方框、箭头、判断节点        |

举个电商产品的例子：

**产品路线图**可能是：

- 第一季度：优化商品搜索
    
- 第二季度：上线会员体系
    
- 第三季度：增加直播购物
    
- 第四季度：拓展海外市场
    

它是在讲：**产品接下来往哪里发展。**

而“用户购买商品”的**产品流程图**可能是：

浏览商品 → 加入购物车 → 提交订单 → 选择支付方式 → 支付成功 → 商家发货

如果支付失败，还会出现分支：

支付失败 → 重新支付 / 更换支付方式 / 取消订单

它是在讲：**用户完成某项操作时，具体经过哪些步骤。**

可以这样记：

> **路线图看未来，流程图看过程。**  
> **路线图决定先做什么，流程图说明具体怎么走。**
