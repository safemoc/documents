哈希（Hash），可以理解成一种“数字指纹”。

它通过一个固定的算法，把任意长度的数据，转换成一个固定长度的结果，这个结果就叫哈希值、摘要或者散列值。

比如把一句话输入哈希算法：

```text
你好
```

可能会得到一串类似这样的结果：

```text
670d9743542cae3e...
```

你输入一本书、一个视频，甚至几百 GB 的文件，最终也都可以得到一个固定长度的哈希值。

哈希有几个重要特点。

第一，输入再大，输出长度固定。例如 SHA-256 不管输入多大，输出始终是 256 位，也就是通常看到的 64 个十六进制字符。

第二，输入只改一点，哈希值通常就会完全改变。

```text
你好
你好。
```

虽然只多了一个句号，但两者的哈希值会相差非常大。这叫“雪崩效应”。

第三，哈希通常是单向的。你可以很容易地从原始数据计算出哈希值，但很难根据哈希值倒推出原始数据。

第四，相同输入一定得到相同结果。所以哈希很适合用来验证数据有没有变化。

例如，你从网上下载一个文件：

```text
下载前官方公布的哈希：
abc123...

你下载后自己计算的哈希：
abc123...
```

两者相同，说明你下载的文件大概率没有被修改或损坏。

不过需要注意，哈希不是加密。

加密的目的是让数据可以在有密钥的情况下被还原；哈希通常不能还原，它主要用于验证、识别和快速查找。

常见用途包括：

- 校验文件是否被篡改
    
- 保存密码
    
- 数据库快速查找
    
- 数字签名
    
- Git 版本管理
    
- 区块链中的交易和区块验证
    

可以用一句话概括：

> 哈希就是把一份数据，通过算法生成一个固定长度、几乎独一无二的数字指纹。


## 以常见的 SHA-256 为例，它大致经历以下过程。
### 第一步：把数据转换成二进制

计算机不会直接处理“你好”或者“ABC”，而是先把它们转换成字节。

例如 ASCII 编码下：

```
A = 65 = 01000001
B = 66 = 01000010
C = 67 = 01000011
```

所以 `"ABC"` 会变成一串二进制数据。

### 第二步：补齐数据长度

SHA-256 不会一次处理任意长度的数据，而是每次处理一个固定大小的数据块：

```
每块 512 位
```

如果原始数据不够 512 位，就按照固定规则补充：

```
原始数据 + 一个 1 + 若干个 0 + 原始数据长度
```

例如可以抽象理解成：

```
ABC + 补位信息
```

直到总长度正好能够分成多个 512 位的数据块。

补位很重要，因为它可以让下面两个输入得到不同结果：

```
A
A 后面加一个 0
```

### 第三步：准备初始值

SHA-256 内部有 8 个预先规定好的数字，可以看成 8 个“初始状态”。

类似：

```
A、B、C、D、E、F、G、H
```

实际上每个都是一个 32 位整数。

这 8 个数字最终组合起来，就是：

```
8 × 32 位 = 256 位
```

这就是 SHA-256 中“256”的来源。

### 第四步：进行多轮混合

每个 512 位的数据块，会被拆分、扩展，然后进行 64 轮计算。

每一轮都会使用很多位运算，例如：

```
异或 XOR
与 AND
非 NOT
循环右移
模 2³² 加法
```

例如异或运算：

```
1 XOR 1 = 0
1 XOR 0 = 1
0 XOR 1 = 1
0 XOR 0 = 0
```

循环右移可以理解成，把二进制数字向右移动，右边掉出去的位再放到左边。

例如：

```
10110001
```

循环右移一位：

```
11011000
```

这些操作会把输入的每一个部分不断打散、交叉和重新组合。

可以把它想象成一个搅拌机：

```
输入数据
   ↓
切碎
   ↓
交换位置
   ↓
和内部状态混合
   ↓
再次切碎
   ↓
连续进行 64 轮
```

最终，输入中的每一个比特，都会影响输出中的许多比特。

### 第五步：更新内部状态

一个数据块完成 64 轮计算后，会得到一组新数字。

这组数字再与之前的内部状态相加，形成新的状态：

```
旧状态 + 当前数据块计算结果 = 新状态
```

如果文件很大，有很多个 512 位数据块，就继续处理下一块。

因此，后面的数据不仅受自己影响，也会受前面所有数据的影响。

### 第六步：输出最终哈希

所有数据块都计算完之后，内部的 8 个 32 位数字会被拼接起来：

```
32 位 × 8 = 256 位
```

然后通常用十六进制显示。

因为一个十六进制字符表示 4 位二进制，所以：

```
256 ÷ 4 = 64
```

因此，SHA-256 的结果通常是 64 个十六进制字符，例如：

```
b5d4045c3f466fa91fe2cc6abe79232a...
```

无论输入是一句话，还是一个 100GB 的视频，最终都是 256 位。

不过需要注意：哈希值并不是保存了原始数据。

它更像是把大量信息经过复杂规则，压缩成一个固定大小的“状态结果”。由于输出空间有限，不同输入在数学上必然可能得到相同哈希，这叫哈希碰撞。

只是对于 SHA-256 来说，可能的结果数量有：

```
2²⁵⁶
```

大约是：

```
1.15 × 10⁷⁷
```

这个范围极其巨大，因此随机碰撞的概率非常低。
